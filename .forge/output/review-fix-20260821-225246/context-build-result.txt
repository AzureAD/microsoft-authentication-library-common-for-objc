```objc
- (BOOL)boolForKey:(nonnull NSString *)flightKey
{
    __block BOOL result = NO;  // Default is NO
    dispatch_sync(self.synchronizationQueue, ^{
        id<MSIDFlightManagerInterface> flightProvider = self->_flightProvider;
        if (flightProvider)
        {
            result = [flightProvider boolForKey:flightKey];
        }
    });
    return result;
}
```

**Key Behavior:**
- **Absent Key vs Explicitly NO:** **NOT distinguishable** — both return `NO`
  - When `flightProvider` is nil: returns `NO` (line 140)
  - When key is absent from provider: returns `NO` (delegated to provider)
  - When key is explicitly set to NO: returns `NO` (delegated to provider)
- Returns to synchronization queue to avoid race conditions with barrier write in `setFlightProvider:`
- Thread-safe: Uses `dispatch_sync` to read provider within synchronized queue

## Context Build Summary — PR #1947

### 1. System Context

**`MSIDBrowserNativeMessageGetTokenResponse`** is the serialization layer that shapes the JSON response sent to browser native-message callers (browser extensions communicating with the MSAL broker). It lives in the broker-operation response subsystem at:

`IdentityCore/src/broker_operation/response/browser_native_message_response/`

The PR adds a flight-gated **allow-list sanitizer** to fix an information-disclosure vulnerability (CWE-201): `MSIDTokenResponse.jsonDictionary` passes through `additionalServerInfo` and sensitive fields (`refresh_token`, `client_info`, `foci`, `provider_type`, etc.) that browser callers should never see.

### 2. Dependency Map

- **`MSIDBrowserNativeMessageGetTokenResponse`** → calls `MSIDTokenResponse.jsonDictionary` (source of the leak), `MSIDFlightManager.boolForKey:` (gate)
- **`MSIDTokenResponse.jsonDictionary`** → emits: all `additionalServerInfo` entries, `refresh_token`, `access_token`, `id_token`, `token_type`, `expires_in/on`, `scope`, `req_cnf`, `state`, `provider_type`, `client_app_version`
- **`MSIDFlightManager`** → singleton, thread-safe via `dispatch_sync`; `boolForKey:` returns `NO` when provider is nil or key is absent — absent and explicit-false are indistinguishable
- **`MSIDFlightManagerMockProvider`** → test mock with `boolForKeyContainer` dictionary; nil key → `[nil boolValue]` → `NO`
